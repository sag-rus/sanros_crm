# Панель Comfort Booking

Пункт после TL Content API. Название объекта открывает публичный URL в новой вкладке. Поиск без сохранения результатов в CRM: название, полная цепочка направления, ID сайта и ID Comfort Booking. Порядок задаёт API сайта: pending → approved → disabled, дата создания по убыванию внутри группы.

Объекты и состояние не копируются в БД/кеш CRM. В PHP-сессии только CSRF. Данные таблицы живут в памяти браузера, ответы no-store. Dedicated endpoint comfort_booking.php не использует legacy mysql.php dispatch/history_global. Пользователь проверяется по текущему паролю и активной сессии БД: права >=2 для просмотра (как TL), >=3 для модерации. У pending зелёная btn-success «Одобрить» и красная btn-danger «Отключить»; approved — только «Отключить»; disabled — нет кнопок.

Запросы к сайту по существующему VPN, HTTPS с проверкой сертификата домена, HMAC-SHA256 и одноразовым nonce. Секрет root:www-data 0640 в /etc/sanata/comfort-booking-moderation-token. Установить после Git через php tools/install-comfort-booking-moderation.php, ключ подать stdin по защищённому административному соединению. Тот же ключ создан на сайте его установщиком. Не выводить ключ в браузер/журнал/Git. Проверка: php tests/api/comfort_booking_moderation. Серверная часть совместима с PHP 7.1.

Поиск и фильтр статуса выполняются на сайте до пагинации; page/perPage (20/50/100/200), search, status. API возвращает total/page/pages/perPage. Под названием показаны правила отмены действующих тарифов; одинаковые правила сгруппированы, периоды заезда и точка отсчёта сохранены. Форматирование следует Content API Swagger и не меняет расчёт штрафа.

Фильтр направления: `directionId=0` — все направления; положительный ID выбирает направление вместе со всеми потомками. API возвращает полный справочник `directions` в порядке родитель → потомки, с `depth` для отступа и `path` для полной цепочки. Соседние направления отсортированы по названию. Поиск `search` применяется только к названию объекта и обоим ID. Направление, статус и поиск сочетаются до расчёта страниц. «Сброс» очищает все три условия и открывает первую страницу, сохраняя размер страницы. Данные справочника остаются на сайте; СРМ хранит их только в текущем интерфейсе.

Редактор SEO: кнопка «Изменить» в колонке «Объект» доступна сотрудникам с правами 3–6. Bootstrap popup читает/сохраняет H1, Title, Description, Keywords и текст верхнего блока через `editorial-read` / `editorial-save` того же API модерации. Оба действия требуют CSRF и действующую авторизацию. Роль/ID сотрудника берутся на сервере СРМ, а не из формы. Данные и история изменений хранятся только на сайте. Пустые SEO-поля оставляют автоматические значения; пустой summary скрывает верхний блок. Основное описание Content API не редактируется. Конфликт revision возвращается сотруднику без потери введённого текста. Проверки: `tests/comfort-booking-moderation.php`, `tests/comfort-booking-editorial-ui.js` (jsdom).
