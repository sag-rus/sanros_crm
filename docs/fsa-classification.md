# Обновление классификации ФСА

`tools/fsa-refresh.php` показывает план; `--apply` сохраняет его, `--object=60` ограничивает объект, `--force` игнорирует кеш. `--cached-plan` — только предварительная диагностика, применение запрещено.

Источник: GET `https://tourism.fsa.gov.ru/api/v1/export/resorts/{UUID}/get`, Api-Key из `FSA_API_KEY` или файла `FSA_API_KEY_FILE` (по умолчанию `/etc/sanata/fsa-api-key`). Значение ключа не хранится в новом коде. Проверяются TLS, HTTP 200, размер, JSON, идентификатор и обязательные поля. При ошибке прошлые данные не заменяются ошибкой API.

Выбор: только записи всего объекта; название проверяется без юридического владельца в конце, для смены привязки также обязательны одинаковые ИНН и регион. Кандидаты берутся из ранее связанных записей и поиска по названию в существующем справочнике. Корпуса, литеры и отдельные коттеджи исключены. Если несколько действующих записей подходят, автоматического выбора нет. Единственная действующая запись может заменить прекращённые дубликаты. Полноценной загрузки новых записей всего реестра этот API-метод не предоставляет; отсутствующую в справочнике запись следует сначала добавить в справочник и проверить.

Публикуются номер, действительный статус, необязательная дата окончания, UUID, название источника, `scope=object`, время успешной проверки UTC. Отсутствующая дата удаляет прежнее значение. Неподтверждённые/неоднозначные привязки получают `scope=unresolved`; сайт их не выдаёт за классификацию объекта. Остальные привязки справочника к этому объекту очищаются после успешной публикации выбранной записи. Старый массовый fuzzy-импорт отключён.

`object` использует MyISAM: все публикуемые поля изменяются одним условным UPDATE по прежним accr_id/accr_data, который не перезаписывает конкурентное изменение. Связи справочника обновляются после него. Перед изменением сохраняется JSON предыдущей карточки и связей в `/var/lib/sanata-fsa/backups`; данные не находятся в Git. Отчёт: `/var/lib/sanata-fsa/report.json`; ошибки и выполненные обновления: `/var/log/sanata-fsa.log`. Поля объекта передаются на сайт существующей синхронизацией раз в 10 минут (до 50 объектов за проход).

Установка только после commit/push и применения через Git: `php tools/install-fsa-refresh.php`. При первой установке существующий API-ключ извлекается из предыдущей Git-версии загрузчика в приватный файл, без вывода значения. Установщик добавляет cron каждые шесть часов и ротацию журнала. Ответы моложе 20 часов переиспользуются, исходное время проверки не сдвигается; большинство объектов проверяются раз в сутки. Ошибки повторяются при следующем запуске. Отчёт `unresolved` требует проверки привязок, не случайного выбора корпуса.

Проверки: `php tests/fsa-classification.php`; на сайте `php tests/fsa-classification-view.php`. Для отката кода — Git revert; данные восстанавливать из выбранных резервных записей после сверки текущих accr_id/accr_data (не массовым перезаписыванием карточек).
