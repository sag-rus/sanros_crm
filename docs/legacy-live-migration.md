# Перевод старых PRICE-подключений на поиск по датам

Разрешены только 10 явно перечисленных объектов в `tools/legacy-live-migration.php`.
Сопоставление CRM-объекта, старого PRICE property_id и TL provider_id проверяется перед записью.
Наличие записи старой интеграции само по себе не разрешает импорт: нужен маркер подготовленной миграции и отключённый старый импорт.

## Порядок установки и переключения

1. Проверить официальный источник, каталог и положительный поиск с точным составом гостей. Коммит/push всех изменений; установить опубликованные коммиты через Git.
2. Собрать новый каталог на PRICE через `prices:refresh-live-catalogues --force --object=ID`. Старая публикация пока продолжает работать. Обычные импортеры до явного prepare откажутся затронуть старый источник.
3. Дождаться окончания старых сборщиков и взять эксклюзивный файловый lock `/home/rustem/price-tonia-auto-sync-v1/worker.lock` на сайте, **удерживая его до конца переключения**. Это исключает старый пакет, уже прошедший проверку флага перед SQL-lock. Не запускать альтернативный ручной legacy gateway/transport во время миграции.
4. Запустить `php tools/migrate-legacy-live.php plan ID` на каждом сервере. Затем prepare на PRICE (останавливает старый сборщик и доставку), CRM и сайте. Все команды проверяют SQL locks и оставляют резервные копии вне Git. На сайте prepare сохраняет прежнюю публикацию до enable.
5. CRM: `php tools/sbor-live-catalogue.php plan ID`, затем apply. Использовать прежние проверенные CRM ID по external_price_mapping; конфликтующие/непроверенные соответствия останавливают импорт. Сохранить резервную копию. Старые номера и тарифы деактивируются, записи и заявки не удаляются.
6. Передать экспортированный каталог штатным `tools/live-catalogue-sync.php --retry` на сайте. Проверить одинаковые ревизии, количества, CRM ID, фотографии и деактивацию старых записей. На сайте `php tools/sbor-live-import.php enable ID` одной транзакцией выключает старую публикацию и включает новую. Для Бакирово очищается только заранее проверенный старый флаг travelline_id=999 (исходное значение сохранено в backup).
7. Выполнить реальные публичные поиски без отправки заявок. Проверить отображение и работу проверяющего кода CRM без записи заявки. Завершить PRICE командой `php tools/migrate-legacy-live.php complete ID` после получения совпадающих квитанций доставки. Освободить worker.lock.

## История и восстановление

Таблицы external_price_snapshot, external_price_mapping и заявки не удаляются. active_snapshot_id сохраняется; import_enabled/publish_enabled переключаются в 0. Новая схема использует price_live_catalogue, прежние нативные ID сохраняются при однозначном сопоставлении. Исторические заявки с дневными строками суммируются прежней проверкой и проверяются через новый поиск без изменения их суммы.

Подготовку можно повторять: маркер и backup не перезаписываются. При ошибке импорта публикация сайта остаётся старой до enable; исправить причину и повторить штатный импорт. CRM room — MyISAM: транзакция не откатывает эти строки, поэтому нужны сохранённая резервная копия и повторный импорт. Нельзя без проверки повторно включать старые загрузчики после импорта нового каталога. Восстановление данных выполнять только отдельной проверенной и версионированной миграцией из сохранённых backup.

Ежедневный live-refresh, доставка, кеширование, диагностика и проверка новых заявок используют существующий общий процесс.
